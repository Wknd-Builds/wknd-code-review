# Dependency And Supply Chain Review Reference

Source snapshot: 2026-08-06.

Primary sources:
- npm package-lock documentation: https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/
- npm scripts documentation: https://docs.npmjs.com/cli/v11/using-npm/scripts/
- OpenSSF Scorecard: https://scorecard.dev/
- GitHub Dependabot documentation: https://docs.github.com/code-security/dependabot
- SLSA framework: https://slsa.dev/spec/v1.0/

Use this reference when reviewing package changes, lockfiles, package manager changes, engines, install scripts, transitive dependency risk, vulnerabilities, changelogs, major upgrades, or risky build tooling.

## Review Checklist

- Compare manifest and lockfile changes. Ensure lockfiles are present, generated by the expected package manager, and consistent with workspace policy.
- Review why each direct dependency is needed, whether a smaller native/platform alternative exists, and whether it enters server, client, build, or mobile runtime code.
- Treat major version upgrades, framework/runtime dependencies, auth/security libraries, build tools, package managers, and native modules as higher risk.
- Check changelogs, release notes, migration guides, deprecations, engine requirements, peer dependencies, and breaking changes.
- Review lifecycle scripts, postinstall behavior, binary downloads, native compilation, code generation, and package-manager config changes.
- Watch for dependency confusion risk, renamed packages, typosquatting, abandoned packages, unpinned registries, git URL dependencies, and unexpected tarballs.
- Assess transitive risk when lockfile diff adds many packages, new maintainers, native binaries, network installers, or build-time execution.
- Check vulnerability reports in context: reachability, exploitability, affected versions, patch availability, and whether the change introduces or fixes exposure.
- Verify runtime versions and engines match CI, Docker, deployment, and developer environments.
- Ensure dependency changes are covered by tests that exercise the behavior touched by the library.
- Review supply-chain-sensitive CI changes: install flags, registry tokens, provenance, cache restore, artifact upload, and secret exposure.

## Common Review Smells

- Manifest changes without lockfile updates, or lockfile churn without a clear manifest reason.
- Major upgrade has no changelog, migration guide, or targeted tests.
- New package adds install scripts, native binaries, or broad transitive tree for a small utility.
- Package manager, registry, or engine changes are mixed into unrelated feature work.
- Security fix updates a package but leaves vulnerable transitive copies through another path.
- CI install flags disable lockfile enforcement or run scripts unexpectedly.
- Client bundle receives a server-only SDK, polyfill, or build tool dependency.

## Primary-Source Refresh Triggers

- Dependency, package manager, lockfile format, runtime engine, or build-tool upgrades.
- Security advisories, CVEs, Dependabot alerts, malicious package reports, or compromised maintainer incidents.
- New lifecycle scripts, native modules, binary downloads, code generators, registries, package-manager config, or provenance requirements.
- Framework major versions, auth/crypto libraries, database clients, mobile native modules, bundlers, and transpilers.
- Large lockfile churn, unexplained transitive additions, or release notes that mention breaking runtime behavior.
